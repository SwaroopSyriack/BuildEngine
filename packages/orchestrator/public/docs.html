How this is wired up

Every screen talks to the buildEngine orchestrator that serves this page. There is no demo data.

1 · Same server, same origin

The orchestrator (packages/orchestrator/main.js) serves this frontend and the JSON API from one Express process, so js/config.js's baseUrl defaults to this page's own origin. Point it elsewhere from the settings gear in the nav.

Pages never call fetch() directly — they use helpers in js/api.js, which unwrap the backend's { message, result } envelope and derive UI fields (a project's status is its latest deployment's status).

2 · Routes in use

Deployments need the worker running. POST /deploy/:id only inserts a pending row — packages/workers/main.js claims it, builds it in Docker and uploads it to S3.

4 · Auth

POST /auth/login and /auth/signup set an httpOnly session cookie and return a token. The frontend keeps that token and sends it as Authorization: Bearer <token> too, so auth also works when the page is served from a different origin. Any 401 sends you back to the sign-in page.
